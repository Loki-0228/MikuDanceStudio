# 未变化模型的顶点缓存

缓存已使本机 StageNoRay 和 ray 场景的低比例预览减少整帧耗时。固定第 0 帧的后台对照中，新版从 100% 缩至 25% 后，整帧耗时分别减少 30.4% 和 31.0%。这些数值衡量静态姿态下的渲染吞吐，不是动画播放帧率。

本轮接续 [StageNoRay GPU 计时](STAGE_NO_RAY_GPU_TIMING_20261015.md)。前序已确认缩小预览能减少绘制区间，但每帧重复的模型更新抵消了收益。本轮缓存输入未变化的模型顶点，MME 的全部特效绘制继续执行。

## 缓存范围

连续两次更新的输入相同后，保留已经计算并上传的模型本体与描边顶点。之后逐字节比较骨骼矩阵、表情权重、描边颜色与宽度、影响描边的相机距离、UV 布局和缓冲区身份。输入变化时立即重新计算，不使用浮点容差或哈希碰撞判断。

正常加载的模型由宿主管理几何数据。加载器登记模型，已知的几何写入入口使缓存失效，无需每帧扫描整份顶点数据。未登记模型采用完整输入快照比较，单模型快照最多 256 MiB，总计最多 512 MiB；超限或分配失败时继续正常计算。正常加载的这两组工程没有分配大块几何快照，仍有少量比较键和管理结构的内存开销。

模型卸载、重新加载、顶点计算设备切换和设备重置会清除对应缓存。直接 CPU 更新、GPU 输入准备和两处 PMD 保存预处理会使旧结果失效。后续新增修改源几何或表情定义的入口，也必须在写入前调用 `model_vertex_cache::Invalidate`。

缓存不会跳过物理、骨骼更新、MME、阴影、透明绘制或时间抗锯齿。特效中的时间参数仍更新。此次没有调整 MME 内部纹理尺寸、阴影设置、采样数或最终输出尺寸，也没有添加菜单或工程选项。本报告记录的第一轮构建仅启用完整包；后续已将缓存纳入最小包，并增加相机移动时仅更新描边的路径，见[后续验证](CAMERA_PREVIEW_CACHE_20261015.md)。

## 前后对照

场景为 `D:/MMD-Next/tests/ToonGlass_Ray/UserFile/StageNoRay.pmm` 与同目录的 `Stage.pmm`。后者显式加载对应效果分配。两者均使用真实 MME，保留工程显示设置，关闭物理和地面网格，固定第 0 帧。硬件为 NVIDIA GeForce RTX 4070 Laptop GPU。

每个场景按旧版、新版、新版、旧版运行。每个进程按 100%、25%、25%、100% 测量，每段预热至少 0.5 秒，再测至少 4 秒。末尾等待已提交的 GPU 工作完成，总耗时除以总帧数。测量期间没有构建、截图读回、GPU 时间戳或逐次绘制钩子。截图在每段计时结束后生成。

主画面为 725×406 和 181×102；宿主阴影为 8192×8192 和 2048×2048。这是前序已有的预览缩放行为，前后两个版本相同。

| 场景 | 预览比例 | 旧版 ms/帧 | 缓存版 ms/帧 | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| StageNoRay | 100% | 22.450 | 8.778 | 60.9% |
| StageNoRay | 25% | 22.081 | 6.108 | 72.3% |
| Stage，ray | 100% | 26.003 | 14.535 | 44.1% |
| Stage，ray | 25% | 25.929 | 10.034 | 61.3% |

每格合并四个采样段，按总耗时除以总帧数计算。共计 9,835 个正式测量帧。旧版部分组的段间极差占中位数约 11.5%～22.9%，新版约 2.8%～6.9%。全部数据均保留，没有删除慢样本。收益大于本轮波动，但不应将表中的百分比视为所有工程的固定收益。

独立诊断帧中，StageNoRay 的 6 个模型更新合计为 0.039～0.140 ms，ray 的 11 个模型为 0.046～0.051 ms。诊断帧包含观察钩子，未混入表中的正式数据。这些数字表示缓存命中后的检查时间，不是运动模型的蒙皮时间。

## 效果核验

- 492 组输入变化对照通过，覆盖 PMD、PMX 附加 UV 0～4、骨骼平移及仿射变换、表情、分组表情、UV、描边、相机参数、几何修改、缓冲区更换、卸载和设备选择。每组比较正常重新计算后的本体与描边顶点字节。
- 两个实际工程通过 136 组模型缓冲区对照，其中 128 组确实命中缓存。每次命中后强制重新计算，再比较本体与描边字节，结果一致。ray 的一个模型没有可缓存几何。
- 原生与 MME 抗锯齿回归各通过 854 项，包含 TAA 相机运动、骨骼变形、SMAA T2x 两档运动矢量、缩放、重置和菜单选中状态。
- 描边回归通过。独立设置目录中的 GPU/CPU 回归通过 120 项，覆盖 PMD/PMX UV 步长、设备回退和菜单。

最终截图另行保留。ray 的 25% 前后截图逐像素一致；100% 前后存在 11～32 个像素差异，最大通道差为 5，同版本重复运行也有少量差异。StageNoRay 同版本重复运行已有 24,864～51,579 个像素差异，不能将其截图作为逐像素一致的证明。该工程的树叶和云特效读取 `TIME` 并更新风场，本轮没有冻结它们。效果核验以模型缓冲区逐字节对照、完整绘制流程和抗锯齿回归为依据，不宣称所有最终截图完全相同。

PMM、对应 EMM 及抗锯齿测试模型的源文件校验值未变化。实现使用通用 CPU 与 D3D9 功能，没有新增 NVIDIA 专用调用；本轮没有 AMD 实机验证。

## 适用边界

缓存收益来自输入未变化的模型。静态舞台、暂停画面和重复姿态更容易命中。角色持续运动、表情变化或相机移动导致描边距离改变时，相关模型继续完整计算。MME 固定尺寸目标、复杂材质和大量绘制提交仍限制缩小预览后的速度。本轮没有测量实际播放时的帧率，也没有证明运动工程能获得相同比例的收益。
