# 云粒子透明排序实验记录

## 验收状态

**本次结果是未通过验收的实验，不是已完成修复。** 标准半透明云层的蓝色重叠硬边已经在候选画面中改善，但 MME 候选存在严重性能回退及操作叠层消失。生产源码未合入 `main`，正式 `build/Release` 未被替换。

用户确认的实际条件是 MME 已加载、云模型未启用 `Cloud.fx`。`Cloud.fx` 的透明裁切是原版 MMD 缺少透明排序时的替代方案。裁切与正确排序的标准 Alpha 混合有不同画面，不能混作同一缺陷，也不能通过提高 AlphaRef、关闭混合或启用 Cloud.fx 来验收本次修复。

## 已确认原因

素材为 `D:/MMD-Next/tests/ToonGlass_Ray/UserFile/cloud.pmm`。云模型包含 95,400 个顶点、31,800 个三角形、15 个材质；材质使用同一张带连续 Alpha 的 `cloud.tga`。

修复前的材质内部排序不会改变材质之间的提交次序。连续云材质的总三角形数量超过原生跨材质排序的 8,192 个三角形上限，导致该组保留原始顺序。前面的半透明面写入深度后，后面的云粒子被深度测试拒绝，形成明显的蓝色重叠边缘。

MME 还有一个独立限制：`RenderNativeOrderedAlpha` 只要发现 `MMEffect.dll` 已加载就提前返回。即使云模型没有自定义效果，原生跨材质排序也不会执行。

模型自身的 EMD 默认指向 Cloud.fx，直接加载原始 PMM 会自动启用它。为准确复现用户条件，本次在本地实验目录保存了字节不变的 PMM 副本及同名 EMM：云模型明确设为 `none`，配件的 ikParticle.fx 保留启用。未修改原始素材、Cloud.fx 或用户工程。

## 候选行为及限制

原生路径检查连续材质的完整渲染属性、贴图和 PMX 实时材质 Morph 通道是否一致。大于原有组上限的等价材质使用一个临时索引流整体排序。CPU 原始索引不变，描边和阴影仍使用原材质范围。这是同模型内等价材质的优化，不代表任意跨模型透明问题已经解决。

MME 中，相同的 PMX 属性并不保证相同的效果分配或子集可见性。实验版保留每个三角形的原材质编号，只合并排序后连续属于同一材质的三角形。该方法在当前视角产生 26,995 次绘制，画面改善但成本不可接受。三角形质心深度排序仍不等于逐像素精确透明，穿插三角形仍可能需要进一步处理。

一次屏幕网格依赖合批实验将调用降至 20,461 次，带诊断日志的短采样仍约 121 ms。与完整排序存在 3,273 个像素差异，最大通道差 4。该实验未进入保留候选；源码另存为本地失败样本，不作为性能或画质验收依据。

只读诊断曾核对本机 MME 的运行时效果分配，证实主目标上的云效果为空，而配件仍有自定义效果。私有 DLL 结构访问仅保留在本地诊断样本，未提交到生产候选。`MMHack.IsEffectFileUsed` 表示 MMD 内置 effect 路径，不能用来判断是否分配了 Cloud.fx 等自定义效果。

MME 候选的操作按钮及 FPS 文字叠层消失尚未解决。因此，该路径没有通过完整画面验收，性能数据也不能作为等工作量下的优化收益。
