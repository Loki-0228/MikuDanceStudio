# 动态阴影共用范围与分辨率计算

## 2026-10-13 实现更新

当前完整包从实际 MMD 9.32 的光源投影变换生成参考矩阵。模型包围盒已在覆盖范围内时保留该矩阵；超出时只扩展必要的轴，并处理齐次 W 接近零的情况。异常光向使用安全投影。原版光源网格会随相机移动，当前验收检查沿同一光线的世界坐标保持相同阴影 UV，不再要求平移相机后矩阵逐字节不变。

固定与动态模式共用 `ShadowDistance()`，防裁切不回写项目或关键帧。动态需求根据实际投影的局部 UV 雅可比、视口和视距计算，保留精细端倍率、分辨率升降迟滞，以及远景屏幕包围盒的上限。实际分配最低为 512，最高受普通/美影档和硬件限制。

`Data/adaptive_shadow.ini` 第一行保存动态精度开关，命名键 `filter_enhanced` 保存独立滤波开关。旧文件中的第二个纯数值字段仍被忽略。滤波从当前 GPU 纹理读取尺寸，不通过美影勾选状态推测尺寸，因此动态分配变化会更新采样参数。

最新防裁切检查在 MME 环境中通过两模式、固定/动态及相机平移共八组。此前独立候选的十四组检查还覆盖轨道旋转、极轴光源和可见大小需求，近景 2048、远景 512。证据位于 `.local/artifacts/shadow-grid-candidate-20261013/`。

## 2026-10-12 历史实现与验收

以下记录描述早期正交拟合实现及当时测量，供追溯使用；当前投影和分配结果以以上更新及最新测试记录为准。


动态缩放与固定模式现在共用 `ShadowDistance()`。滑块、数值框和阴影关键帧读取同一份值；实际投影在这个范围基础上增加模型覆盖保护。切换「动态缩放」只改变阴影贴图的分配策略，保留范围的完整浮点值。两种模式都显示「阴影范围」，左侧精细，右侧远处。

## 原因

旧实现用 `ShadowDistance()` 控制投影覆盖区，用另一个 `DynamicShadowPrecision()` 控制动态分辨率倍率。切换时复制滑块位置，只改变了界面显示。动态模式下继续向右拖动，原来的窄覆盖区仍参与绘制。平移视点使覆盖边界扫过模型时，自阴影会成片消失。

现在移除独立精度字段。`Data/adaptive_shadow.ini` 只保存动态缩放是否开启，读取旧文件时忽略第二个精度字段。项目与关键帧中的阴影范围仍沿用原保存格式。精细端的采样倍率直接从这份范围值计算，不另存一套滑块状态。

## 覆盖保护

高精细度不再以裁切模型为代价。每次绘制阴影时，程序读取当前变形后的模型顶点，以及可见附件经过世界变换后的范围，计算场景包围盒，再将八个角转换到光源坐标。

横向和纵向使用能容纳整个包围盒的正方形覆盖区；前后深度也要容纳整个包围盒。每侧增加半尺寸的 5% 作为余量，且不少于 0.25 个模型坐标单位。实际范围取滑块请求范围和这个安全范围中的较大值。固定和动态两种分辨率策略都应用此保护。

投影中心跟随模型范围，不随镜头平移。没有几何数据时才使用视点作为后备中心。安全范围只影响当帧投影，不回写滑块、项目或关键帧。滑块继续向精细端移动而范围已达到安全下限时，实际覆盖区保持不变。

## 范围和像素密度

滑块位置 `p` 的有效范围为 0 到 9999，对应原有范围参数：

```text
s = (10000 - p) / 100000
k = 2（模式 1），或 3（模式 2）
请求的光源平面覆盖宽度 L_requested = 2 / (k × s)
实际覆盖宽度 L = max(L_requested, 包围盒所需宽度及余量)
```

`s` 是投影比例，数值越小，实际覆盖范围越大。以模式 1 为例：

| 滑块位置 | 请求覆盖宽度，模型坐标单位 |
| --- | --- |
| 0 | 10 |
| 8875 | 约 88.89 |
| 9500 | 200 |

覆盖宽度与分辨率分开计算。动态模式读取拟合后的投影矩阵，按实际覆盖宽度估算整个覆盖区投到画面上需要多少像素：

```text
Q = max(画面宽度 × abs(P00), 画面高度 × abs(P11))
精细端采样倍率 F = 2 ^ clamp(40 × s - 2, 0, 2)
透视相机的需求 N = 1.25 × Q × L × F / (2 × z)
正交相机的需求 N = 1.25 × Q × L × F / 2
```

`P00`、`P11` 来自当前相机投影矩阵，`z` 是场景包围盒在镜头前方的最近深度。包围盒跨过相机平面时，深度下限为 0.0001；全部位于镜头后方时使用最低分辨率需求。`1.25` 留出采样余量。扩大覆盖范围或靠近模型会增加需求，拉远镜头会降低需求。正交相机的需求不随镜头距离改变。

采样倍率在滑块 5000 及右侧为 1，向左提高，最精细端为 4。这恢复了此前最精细档的采样需求，避免覆盖保护生效后滑块继续向左却完全不影响分辨率。

包围盒包含屏幕外的几何。大型三角形可能覆盖画面，但所有顶点都在屏幕外。旧算法把这种情况误认为没有几何需求，会过早降低分辨率。保守估算可能为屏幕外的近处模型保留较高分辨率，换取平移时稳定的像素密度。

覆盖保护扩大范围时，按 `实际宽度 / 请求宽度` 补偿分辨率上限，并向上选择二次幂。最多增加一档：普通档由 2048 提高到 4096，美影档由 4096 提高到 8192。未扩大范围时仍保留原上限。此补偿同时用于固定与动态模式；固定模式直接使用补偿后的上限，动态模式按当帧需求选择分辨率。

实际尺寸还受显卡能力限制，分配失败时逐档回退。动态模式保留原有升降阈值：超过当前尺寸的 1.1 倍时升级，低于 0.4 倍时降级，避免边界附近频繁重新分配。

## 边界

保护覆盖参与范围计算的模型和附件。大场景或相距很远的多个模型会扩大覆盖区；达到分辨率上限后，每个模型单位获得的像素数会减少。第三方 FX 在顶点着色器中额外产生的位移没有计入此包围盒。

本次没有改变光源、自阴影模式或第三方 FX。包围盒读取遍历全部顶点，避免稀疏采样漏掉极值；尚未测量这一步的性能开销。独立的原版功能兼容构建继续使用原版投影，正式 MMS 完整构建使用上述覆盖保护。

## 精细度补偿和动态缩放实测

测试入口为 `tests/shadow_quality_runner.py`。视口为 960×720，滑块为 0，开启美影。测试从显卡的阴影表面和纹理分别读取实际尺寸，核对两者一致，并逐步比较投影矩阵和范围参数。每种阴影模式在同一进程内执行以下往返：

| 相机距离 | 开启动态缩放 | 关闭动态缩放 |
| --- | --- | --- |
| 720 | 512×512 | 8192×8192 |
| 180 | 1024×1024 | 8192×8192 |
| 45 | 4096×4096 | 8192×8192 |
| 12 | 8192×8192 | 8192×8192 |
| 180 | 1024×1024 | 8192×8192 |
| 720 | 512×512 | 8192×8192 |

上述序列中投影矩阵和滑块值保持不变。原生路径记录在 `.local/artifacts/shadow-quality-after/1791815375420080000/`。此记录采用美影档；随后将普通档的补偿上限限定为 4096，保留两个质量档位的区别，美影档计算不变。

最终代码加载原版 MME 后，两种阴影模式的 24 次缩放得到相同结果，记录在 `.local/artifacts/shadow-quality-mme/1791815625286410200/`。普通档另做大型三角形检查：两种模式各三个近景位置均分配 4096，远景均回到 512，共八组通过，记录在 `.local/artifacts/shadow-quality-large/1791815636582284800/`。最终原生阴影与 SM2 覆盖测试均通过，包含最高采样倍率、补偿上限和显卡尺寸限制检查。

相同模型、镜头距离 45 下，修改前动态模式为 1024×1024，修改后为 4096×4096，线性采样密度提高四倍；固定模式由 4096×4096 提高到 8192×8192，线性采样密度提高两倍。两版覆盖宽度均约为 16.3679。修改前记录在 `.local/artifacts/shadow-quality-before/1791815208638751300/`，两组目录均保留截图。

截图像素检查确认两种模式各有 436 个像素发生超过 2 级的颜色变化，变化范围位于阴影边界。原生和 MME 的远景往返截图差异均为 0 像素，记录在原生路径目录的 `pixel-audit.json`。

此测试模型的新固定模式密度约为每单位 500.49 个采样点。旧版未保护覆盖时，模式 1 最精细请求区对应 409.6，模式 2 对应 614.4。8192 上限足以补偿前者，但没有完全恢复后者；不能把提高分辨率表述为任意模型都保留原裁切区域内的最高密度。

## 当前构建复测（含锁暝模型）

本轮重新编译当前源码的 `frame_benchmark` 和 `frame_benchmark_mme`，两者链接正式程序共用的渲染实现。后者强制检查 `MMEffect.dll` 已加载。设备为 NVIDIA GeForce RTX 4070 Laptop GPU，视口 960×720，美影开启，阴影范围滑块为 0。

受控遮挡模型和 `鸣潮_锁暝1.0.pmx` 均执行原生／原版 MME、模式 1／模式 2、动态开／关、六个镜头距离步骤，共 96 次实际渲染后的尺寸读回。结果均与上表一致：动态模式按 512、1024、4096、8192、1024、512 往返，固定模式始终为 8192。读回直接来自显卡阴影表面和纹理，两者尺寸一致。全部步骤保留同一范围值及投影矩阵。

受控遮挡场景在距离 45 下比较动态 4096 与固定 8192，四组画面各有 193 个像素变化超过 2 级，差异位于阴影边缘。远景往返前后逐像素一致。八组投影检查中的模型顶点全部位于阴影范围内。

锁暝模型有 85,217 个顶点、415 个刚体和 584 个关节。首轮测试捕获了最后一次物理更新前的投影参考，而缩放循环使用更新后的姿态，触发覆盖不一致检查。测试入口现先渲染完成该姿态再保存参考，缩放期间不推进物理，随后四组检查全部通过。此处只修改测试准备步骤，未改动产品的阴影计算。

锁暝模型的四组远景往返截图均完全一致。近景即使两次使用相同的 8192 尺寸，仍有 41 至 97 个像素变化超过 2 级，因此不能把该模型近景的全部像素差异归因于分辨率；阴影边缘变化的独立证据使用上述受控遮挡场景。本轮不作性能结论，也不代表所有第三方 FX 的自定义阴影都会随此开关改变。
