# 相机移动缓存与最小包支持

在[未变化模型缓存](MODEL_VERTEX_CACHE_20261015.md)基础上，模型的骨骼、表情及源几何未变化，而相机或描边参数变化时，CPU 蒙皮路径只更新描边缓冲区。本体顶点继续使用已上传的结果。

需要重新计算描边时，首次完整更新保留每个顶点 32 字节的位置、法线及描边输入。后续从这份紧凑数据更新描边，不读取主 D3D9 顶点缓冲区。静止相机不额外分配这份数据。骨骼或表情变化、源几何失效、模型卸载和设备重置会释放或使缓存失效；分配失败时恢复完整计算。

单模型缓存上限为 256 MiB，总计 512 MiB，与未登记模型的输入快照共用预算。StageNoRay 和 ray 的相机移动检查分别保留约 22.5 MiB 和 22.6 MiB 的描边输入。

完整包与 `mmd932` 最小包均启用相同的模型缓存、CPU 蒙皮及表情等价计算优化。最小包仍使用原有菜单、阴影及分辨率规则，不新增预览缩放选项。GPU 蒙皮结果的相机描边更新仍走原路径；完整结果缓存适用于 CPU 和 GPU 两种路径。

## 正确性验证

- 两种构建各通过 611 组本体与描边逐字节对照，覆盖 PMD、PMX 附加 UV 0～4、连续相机运动、描边颜色和宽度、自阴影状态、骨骼变化及失效处理。
- 两种构建均通过实际 StageNoRay 和 Stage（ray）工程检查，每种构建 136 组，共 272 组。每种构建中 128 组命中缓存，其余为没有可复用几何的模型；全部与立即完整重算的结果逐字节一致。
- 完整版原生和真实 MME 抗锯齿回归各通过 854 项。最小包原版界面通过 677 项，原版状态通过 32 项。两种构建均通过描边回归。
- 实际场景检查固定 CPU 蒙皮，防止自动设备选择影响路径覆盖。ray 首帧可能因编译特效超过按时间设置的预热窗口，因此测试要求至少八帧且不少于 0.5 秒预热。
- 测试不修改源 PMM、EMM 或模型；没有改变特效纹理、采样数、阴影精度或绘制顺序。本轮没有 AMD 实机验证。

## 性能记录状态

本轮相机移动 ABBA 测量尚未完成。第一次采样检测到并行编译，已保留为无效记录，不能用于性能结论。前一报告中的静止相机数字不能替代本轮结果。

计划比较同一测试程序中关闭、启用、启用、关闭描边缓存，固定模型第 0 帧并连续移动相机。完整版每轮按 100%、25%、25%、100% 预览测量，最小包保持原有 100% 分辨率，每段至少四秒，段末等待已提交的 GPU 工作完成。该数据衡量渲染耗时，不代表动作和物理播放帧率。

本轮原始记录位于 `.local/artifacts/outline-cache-20261015/`。有效正确性记录为 `full-r4-verify-*`、`minimal-r4-verify-*`、`aa-r4-native`、`aa-r4-mme-retry` 和两档 `*-r2-*-tests` 日志。GPU 压紧读回实验及固定阴影目标缩放不属于本报告已完成范围。
