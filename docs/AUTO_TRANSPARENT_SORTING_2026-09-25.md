# 自动透明材质排序开关与默认美影

2026-09-25：显示菜单新增「开启自动透明材质排序」，新程序实例默认勾选。右上角「美影」默认勾选，实际阴影贴图同步设为 4096×4096。

## 开关行为

开启透明排序时沿用已验收的材质内三角形排序及有预算限制的跨材质、跨模型排序。关闭时跳过这两处排序，保留不透明像素预通道、描边和阴影处理。此开关不启用已停用的全量排序实验。

排序会改写 GPU 索引。关闭后的第一次绘制把所有已加载模型的 GPU 索引恢复到 CPU 原始顺序；恢复成功后清除每个应用实例的脏标记，关闭稳态无需每帧锁定或回写。锁定失败保留标记，后续绘制重试。PMX 与 PMD 分别使用加载器原有的索引来源。

菜单项采用命令 303，追加到显示菜单尾部，不移动原菜单按位置翻译的条目。语言切换按命令 ID 更新文案和勾选。与同期 PMM 扩展整合后，项目可保存透明排序选择，格式和兼容规则见 [PMM v2 扩展](PMM_V2_EXTENSIONS.md)。

美影控制阴影贴图精度。启动代码复用现有 556 命令，在勾选时设置 4096 并释放旧尺寸资源，由渲染路径重建；取消勾选恢复 2048。自阴影模式仍由原有自阴影控件控制。

## 后台正确性验收

验证使用隐藏窗口与 D3D9 渲染目标回读，没有显示、置顶窗口或桌面截图。洛希极限原始 PMX 含 183698 个顶点。启动默认值、中文文案、三语切换、菜单不重复及美影 2048/4096 切换均通过。

在实际模型上，开启排序时有 577927 个 GPU 索引不同于源索引。关闭后差异为 0，重新开启后为 577925。已在隔离版本及包含同期 GPU 蒙皮、PMM 扩展的正式主分支各验证一次。主分支验证使用自动选择的 RTX 4070 Laptop GPU，18 次蒙皮更新无 CPU 回退。

两侧 `model_alpha_regressions`、`model_edge_regressions`、`transparent_material_order_regressions` 均通过，共 6 次。未把历史全量排序实验的遮挡用例作为本次开关验收依据。

同质量的两张 1280×720 面部图，逐通道平均绝对差不超过 0.000089/255；Grass 不超过 0.000008/255。不同默认阴影精度的图像存在预期阴影差异，不能用作画面完全一致的对照。

## 验证工具和产物

`frame_benchmark --fine-shadow 0|1` 明确控制质量，用于两个版本的同条件对照。不传该参数时保留程序启动默认值。`--verify-view-toggles` 在原生模型渲染场景中校验默认值、菜单语言、真实命令切换和 GPU 索引恢复，失败返回非零退出码。JSON 的 `view_options` 记录启动值、实际阴影宽度和校验结果。

本次产物位于 `.local/artifacts/auto-transparent-toggle/`：

- `abba/manifest.json`：两个 build 的提交、工作树状态、CMake 缓存、EXE 与素材哈希、每次命令及退出码。
- `abba/summary.json`、逐次 JSON、日志和 PNG：原始测量及汇总。
- `toggle-verification.log`、`integrated-toggle-verification.log`：隔离与正式分支的功能校验。
- `image-comparison.json`：渲染目标图像的像素差异统计。
- `final-manifest.json`：正式 Release、基准驱动和生产源文件哈希，以及 DSH 子任务 ID。
- `build_pair.py`、`run_pair.py`、构建和 CTest 日志：可复核的执行记录，包括早期缺少测试构建选项和基准驱动编译失败记录。

初始 `manifest.json` 记录的是并行任务期间保存的旧运行目录，不作为本次受控 build 的来源证据；以 `abba/manifest.json` 为准。修改前后的构建目录和 Git 分支保留，不向根目录新增临时文件。
