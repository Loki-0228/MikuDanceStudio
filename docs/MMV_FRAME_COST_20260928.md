# MMV 加载开销优化与子任务验收

本轮在正式 `main` 完成自由轴兼容修复、快照开销优化和测量有效性检查，已本地提交，未推送。Rou 在**成功完成 MMV 更新**的前后对照中，完整帧批量耗时中位数从 449.48 ms 降到 123.40 ms，约减少 72.5%。这是后台强制编辑器帧的 CPU 提交与最终 GPU 排空成本，不是播放 FPS。

空载 MMV 仍有明显成本，不能据此宣称卡顿全部解决。四次新版结果为 122.30、123.47、123.34、141.55 ms；极差占中位数 15.6%，标记为有波动，全部保留。未加载 MMV 的两次参考为 7.27、8.02 ms。

## 修复与实现

- 原始 Rou 每帧报 `joint/35 : angular limits are inverted`，返回 `MMV_FAILED`。原生 Bullet 的 `lower > upper` 表示自由轴，不能拒绝或交换上下限。现在快照保留原值，继续检查有限数值和刚体引用；作者契约已同步到 [MMV FX 总文档](MMV_FX.md) 与 [循环接口契约](MMV_DEFORMER_INTERFACE_CONTRACT.md)。
- 结构与网格摘要缓存在快照对象内部。复制继承有效缓存；修改相应内容时失效。质量 `+0/-0` 的位模式变化也能被识别，失败候选不改变原快照。
- 冷摘要的版本比较直接比较字段流。FNV 与精确比较共用字段访问清单，顶点、权重和纹理以只读字节段比较，标量按值保存。临时字段数量有上限，超限回到原摘要算法。
- 没有 FX 或物理输出变化时，省去重复的完整场景复制、校验和网格同步。从未改写过 Source 的空层共享只读 Source；有独立 FX 版本历史的层仍复制并归并自身版本。旧查询持有的快照保持有效。
- 有效顶点和权重行不再预先构造错误项字符串，实际失败时仍生成原错误定位。
- 基准记录宿主每次更新的序号及是否接受输出。加载失败、跳过更新、快照拒绝或输出失败不能算有效采样；退出码 20/21 检查插件加载条件，22 标记 MMV 更新失败。参见 [帧基准说明](FRAME_BENCHMARK.md)。

代码提交：自由轴 `e7fd8aa`，测量检查 `538d45e`，空载重复处理 `81b0c8c`，摘要比较 `11066f9`，空层共享 `aa0fd2c`。

## 对照方法

素材为原文件 `D:/MMD-Next/tests/MMD ☆★Rou/☆Rou.pmx`，194,644 顶点、96 刚体、139 关节；没有分配 MMV FX、没有加载 MME。主渲染使用 RTX 4070 Laptop GPU，顶点处理固定 CPU，视口 1280×720，透明排序强度 1，自阴影 1，相机每帧转动 0.08 度。每次预热 10 帧、测量 30 帧，运行两轮 ABBA，另在前后各测一次无插件参考。两侧使用同一基准 EXE，保留原生物理和全部绘制工作量；图像来自渲染目标回读。

原始 DLL 的报错回退不能与成功求解直接比较性能。因此有效基线使用原生产 runtime 对象和依赖库，仅将快照自由轴校验修正；优化版也包含同一修正。基线输入对象、库、源码副本、编译脚本与哈希保存在 `reference-build-input/`。最初失败的原始 DLL 和日志另外保留，未作为有效基线。

配置为 VS 2022 / v143 / x64 / Release，`/O2 /Ob2 /MD`，PERF 和 DIAG 均关闭。起点 HEAD 为 `e8a3327`。工作区原有 CPU+DX9 版本改动两侧一致保留，其补丁及新增源文件已归档；不将脏工作区冒充纯提交构建。

实际执行顺序为无插件、A1、B1、B2、A2、A3、B3、B4、A4、无插件。八次 MMV 运行均接受全部 30 个采样帧，失败计数为 0。基线波动为 1.6%；新版 15.6% 和无插件 9.8% 的波动未剔除，不能把中位数当作稳定上限。

峰值工作集均值约从 1,179 MiB 降至 883 MiB。十张最终 PNG 的 SHA-256 完全相同：`66D5AB648D6EA90F4FDB43B29C2CCA1F794632881482DA390062CADDECD1F11E`。前一阶段约 197～205 ms 的测量和图像同样保留。

独立 CPU 微基准使用 30,000 顶点、三层、40 次采样，两侧分别从生产快照源码编译。总耗时从 91.22/91.24 ms 降到 30.62/31.85 ms；Source 版本归并从约 15.4 ms 降到 0.75/0.85 ms，最终 meshVersion 都为 45。该微基准保留固定的复制和校验序列，用于隔离快照模块，不替代完整程序结果。
