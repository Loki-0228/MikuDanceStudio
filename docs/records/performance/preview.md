## MME 预览缩放与自动重载优化

原始记录：`MME_PREVIEW_OPTIMIZATION_20261015.md`。其中的版本、日期和验证范围沿用原记录。

<a id="record-mme-preview-optimization-自动重载"></a>
### 自动重载

完整包与最小包保留 MME 的「自动重载」开关。开启时，编辑并保存已加载的根 FX 文件仍由 MME 重新编译。关闭时不自动编译，重新开启后会检测期间的修改。

MMEffect 0.37 x64 的自动重载分支约每 100 毫秒检查一次文件时间戳。原实现每次检查都打开文件、读取时间戳并关闭文件。本次只缓存该分支的时间戳查询，用 Windows `ReadDirectoryChangesW` 接收所属目录的变更通知。未变更文件返回已缓存的时间戳；保存、删除、重命名或原子替换使对应文件失效。目录事件检查为非阻塞，每个目录最多每 10 毫秒一次。

编译器加载、手动重载和其他 MME 时间戳查询继续读取文件。每个缓存文件仍有约 30 秒一次的错峰校验。通知溢出使该目录全部文件失效；监听失败、相对路径和无法确认编码的路径回到原始查询。缓存上限为 2048 个文件、256 个目录，不创建轮询线程。缓存不会扩大 MME 原本的 include 依赖重载范围。

挂钩只适用于 SHA-256 已验证且入口指令匹配的 MMEffect 0.37 x64。未识别的 MME 版本保持原行为。实现不依赖 NVIDIA API，AMD 使用相同的 Windows 文件通知路径。

<a id="record-mme-preview-optimization-小预览的固定阴影资源"></a>
### 小预览的固定阴影资源

完整包只缩放已识别的 SoftShadowM4 与 ray 固定阴影资源。粒子状态纹理、查找表和其他未知用途资源保持原尺寸。最小包没有视口渲染比例功能，因此不启用该缩放。

| 实际测试工程 | 资源 | 100% 预览 | 25% 预览 | 导出与恢复 100% |
| --- | --- | --- | --- | --- |
| StageNoRay | SoftShadowRT、ScnMapX、ScnMapY、DepthBuffer | 1024² | 512² | 1024² |
| Stage（ray） | PSSM1～PSSM4 | 2048² | 512² | 2048² |

缩放按二次幂分档，最小尺寸为 512。SoftShadow 同步 `ViewportSize`，ray 同步半纹素采样偏移。原有投影、光照及归一化滤波范围保持不变。小预览允许降低阴影精度，100% 预览和导出恢复特效声明的原尺寸。只在尺寸变化时调用 MME 原有的资源重建过程，不增加每帧绘制。FX 源文件不被修改。

ray 的适配在内存中预处理并编译，仅匹配已确认的主特效结构；无法匹配或编译失败时使用原始编译入口。采样偏移中声明的原尺寸必须与实际阴影资源一致，否则不缩放。资源重建失败时尝试恢复原尺寸，并停用本次进程的缩放优化。

### 预览缩放耗时

当前构建在 StageNoRay 上完成两轮、Stage（ray）上完成一轮 `100% → 25% → 25% → 100%` 测量，采样期间均未检测到并发构建或其他测试渲染。固定模型姿态，使用 CPU 蒙皮并连续移动相机，每段至少四秒，段末等待已提交的 GPU 工作完成。以下为按帧数加权的整帧耗时，不是动作与物理播放帧率。

| 工程 | 预览比例 | 平均帧耗时 | 对应帧率 | 采样帧数 |
| --- | --- | --- | --- | --- |
| StageNoRay | 100% | 8.843 毫秒 | 113.1 fps | 1817 |
| StageNoRay | 25% | 7.334 毫秒 | 136.3 fps | 2185 |
| Stage（ray） | 100% | 14.839 毫秒 | 67.4 fps | 540 |
| Stage（ray） | 25% | 11.026 毫秒 | 90.7 fps | 726 |

小预览平均帧耗时分别减少约 17.1% 和 25.7%。这是当前构建内两种预览比例的比较，不能解释为相对旧版本的提速，也不能拆分为某一项优化的独立收益。StageNoRay 记录为 `integrated-r2-full-StageNoRay-2-candidate/`、`integrated-r2-full-StageNoRay-3-candidate/` 和 `accepted-preview-summary.json`；ray 记录为 `ray-preview-r4-1/`、`ray-preview-r4-1-guard.json` 和 `accepted-ray-preview-summary.json`。

旧版与新版的完整 ABBA 对比，以及早期 ray 预览测量，因并发编译或压缩干扰而未获得有效结论，相关记录已保留但排除。最终 ray 第一轮有效；第二轮启动前检测到其他活动，没有开始采样，因此 ray 只有一轮结果。ray 的尺寸恢复与导出正确性检查已通过。

真实工程中，StageNoRay 每段约四秒有约 2177 次、ray 有约 4617～4653 次自动重载查询命中缓存，未发生实际时间戳文件读取。文件查询减少量与整帧耗时分别记录，不把减少文件查询直接等同于帧率提高。

<a id="record-mme-preview-optimization-gpu-蒙皮传输"></a>
### GPU 蒙皮传输

完整包的 D3D9/MME 蒙皮桥对至少 262144 个顶点、附加 UV 为 0 或 1 的模型增加 GPU 紧凑读回。计算结果仍为原有 112 字节布局；额外的 GPU 整数复制只保留本体与描边实际需要的 48 或 64 字节。小模型及 UV 2～4 使用原路径。自动设备选择的校准缓存版本已更新，旧排名会重新校准。

YYB 的读回量从 32116896 字节降至 13764384 字节，HGrass 从 52765664 字节降至 30151808 字节。两模型均完成五种姿态、五档 UV 的逐字节比较，并在本机 NVIDIA 和 Intel 上通过生产 D3D9 缓冲身份与 CPU 误差检查。此方案仍经过 CPU 读回和 D3D9 上传，并非跨 API 零拷贝。早期诊断计时没有满足独占采样要求，不用于帧率结论。最小包不编入 DX12，但包含共享的模型缓存与文件通知优化。

最终蒙皮后端回归通过 120 组 GPU/CPU 检查，覆盖 PMD/PMX UV 布局、回退、设备设置、菜单和校准缓存失效，记录为 `final-skinning-backend/`。

<a id="record-model-vertex-cache"></a>
## 未变化模型的顶点缓存

原始记录：`MODEL_VERTEX_CACHE_20261015.md`。其中的版本、日期和验证范围沿用原记录。

缓存已使本机 StageNoRay 和 ray 场景的低比例预览减少整帧耗时。固定第 0 帧的后台对照中，新版从 100% 缩至 25% 后，整帧耗时分别减少 30.4% 和 31.0%。这些数值衡量静态姿态下的渲染吞吐，不是动画播放帧率。

本轮接续 [StageNoRay GPU 计时](preview.md#record-stage-no-ray-gpu-timing)。前序已确认缩小预览能减少绘制区间，但每帧重复的模型更新抵消了收益。本轮缓存输入未变化的模型顶点，MME 的全部特效绘制继续执行。

<a id="record-model-vertex-cache-缓存范围"></a>
### 缓存范围

连续两次更新的输入相同后，保留已经计算并上传的模型本体与描边顶点。之后逐字节比较骨骼矩阵、表情权重、描边颜色与宽度、影响描边的相机距离、UV 布局和缓冲区身份。输入变化时立即重新计算，不使用浮点容差或哈希碰撞判断。

正常加载的模型由宿主管理几何数据。加载器登记模型，已知的几何写入入口使缓存失效，无需每帧扫描整份顶点数据。未登记模型采用完整输入快照比较，单模型快照最多 256 MiB，总计最多 512 MiB；超限或分配失败时继续正常计算。正常加载的这两组工程没有分配大块几何快照，仍有少量比较键和管理结构的内存开销。

模型卸载、重新加载、顶点计算设备切换和设备重置会清除对应缓存。直接 CPU 更新、GPU 输入准备和两处 PMD 保存预处理会使旧结果失效。后续新增修改源几何或表情定义的入口，也必须在写入前调用 `model_vertex_cache::Invalidate`。

缓存不会跳过物理、骨骼更新、MME、阴影、透明绘制或时间抗锯齿。特效中的时间参数仍更新。此次没有调整 MME 内部纹理尺寸、阴影设置、采样数或最终输出尺寸，也没有添加菜单或工程选项。本报告记录的第一轮构建仅启用完整包；后续已将缓存纳入最小包，并增加相机移动时仅更新描边的路径，见[后续验证](preview.md#record-camera-preview-cache)。

### 前后对照

场景为 `D:/MMD-Next/tests/ToonGlass_Ray/UserFile/StageNoRay.pmm` 与同目录的 `Stage.pmm`。后者显式加载对应效果分配。两者均使用真实 MME，保留工程显示设置，关闭物理和地面网格，固定第 0 帧。硬件为 NVIDIA GeForce RTX 4070 Laptop GPU。

### 效果核验

最终截图另行保留。ray 的 25% 前后截图逐像素一致；100% 前后存在 11～32 个像素差异，最大通道差为 5，同版本重复运行也有少量差异。StageNoRay 同版本重复运行已有 24,864～51,579 个像素差异，不能将其截图作为逐像素一致的证明。该工程的树叶和云特效读取 `TIME` 并更新风场，本轮没有冻结它们。效果核验以模型缓冲区逐字节对照、完整绘制流程和抗锯齿回归为依据，不宣称所有最终截图完全相同。

PMM、对应 EMM 及抗锯齿测试模型的源文件校验值未变化。实现使用通用 CPU 与 D3D9 功能，没有新增 NVIDIA 专用调用；本轮没有 AMD 实机验证。

<a id="record-model-vertex-cache-适用边界"></a>
### 适用边界

缓存收益来自输入未变化的模型。静态舞台、暂停画面和重复姿态更容易命中。角色持续运动、表情变化或相机移动导致描边距离改变时，相关模型继续完整计算。MME 固定尺寸目标、复杂材质和大量绘制提交仍限制缩小预览后的速度。本轮没有测量实际播放时的帧率，也没有证明运动工程能获得相同比例的收益。

<a id="record-camera-preview-cache"></a>
## 相机移动缓存与最小包支持

原始记录：`CAMERA_PREVIEW_CACHE_20261015.md`。其中的版本、日期和验证范围沿用原记录。

在[未变化模型缓存](preview.md#record-model-vertex-cache)基础上，模型的骨骼、表情及源几何未变化，而相机或描边参数变化时，CPU 蒙皮路径只更新描边缓冲区。本体顶点继续使用已上传的结果。

需要重新计算描边时，首次完整更新保留每个顶点 32 字节的位置、法线及描边输入。后续从这份紧凑数据更新描边，不读取主 D3D9 顶点缓冲区。静止相机不额外分配这份数据。骨骼或表情变化、源几何失效、模型卸载和设备重置会释放或使缓存失效；分配失败时恢复完整计算。

单模型缓存上限为 256 MiB，总计 512 MiB，与未登记模型的输入快照共用预算。StageNoRay 和 ray 的相机移动检查分别保留约 22.5 MiB 和 22.6 MiB 的描边输入。

完整包与 `mmd932` 最小包均启用相同的模型缓存、CPU 蒙皮及表情等价计算优化。最小包仍使用原有菜单、阴影及分辨率规则，不新增预览缩放选项。GPU 蒙皮结果的相机描边更新仍走原路径；完整结果缓存适用于 CPU 和 GPU 两种路径。

## Stage.pmm 的 MME 预览缩放与阴影范围优化

原始记录：`MME_PREVIEW_PERFORMANCE_20261015.md`。其中的版本、日期和验证范围沿用原记录。

本轮使用用户指定的 `Stage.pmm` 复现。MME 中随屏幕大小变化的渲染目标已经跟随预览比例缩小；部分固定尺寸目标和每帧模型处理仍保持原来的工作量。降低预览比例不能消除这些开销。

阴影覆盖范围的全顶点计算已改为 SSE2 批量比较。本机短时 ABBA 对照中，这部分耗时降低约 49%～50%，整帧吞吐提高约 9%～13%。该结果来自固定第 0 帧的重复绘制，不是动画播放帧率，也不代表所有工程的提升幅度。

<a id="record-mme-preview-performance-场景与尺寸观察"></a>
### 场景与尺寸观察

- 工程：`D:/MMD-Next/tests/ToonGlass_Ray/UserFile/Stage.pmm`，使用配套 EMM 和真实 MME DLL。
- 显卡：NVIDIA GeForce RTX 4070 Laptop GPU。
- 加载的 11 个模型保持独立所有权；测试前后 PMM 和 EMM 的 SHA-256 一致。
- 最终构建在原生 D3D9 绘制入口记录目标纹理和视口尺寸。记录过程位于计时区间之外。

| 目标类型 | 100% 预览 | 25% 预览 |
| --- | --- | --- |
| 随屏幕大小变化的主要 MME 目标 | 725 × 406 | 181 × 102 |
| 部分后处理缩小目标 | 362 × 203 | 90 × 51 |
| 观察到的固定目标 | 2048²、1024²、512²、256² 等 | 保持不变 |
| 应用持有的原生阴影纹理 | 8192² | 2048² |

原生阴影纹理尺寸来自资源查询，不等同于 MME 当前绘制到的目标尺寸。此场景在两种预览比例下，都有 137 次绘制落在同一规格的 2048² 目标上。尺寸跟踪按格式与大小分组，不提供特效资源名称，因此不能仅凭此记录断言该目标属于某个具体特效。

本轮没有强行缩小特效声明的固定尺寸资源。这类资源可能承载阴影、查找表或跨帧数据，统一缩放需要另行确认其用途。阶段计时还显示，模型变形与蒙皮、材质提交等 CPU 工作不会随像素数量同比减少。

<a id="record-mme-preview-performance-修改内容"></a>
### 修改内容

`NativeShadowVertexBounds` 在已锁定的顶点缓冲区上同时比较 XYZ 范围，仍读取所有顶点。遇到非有限坐标时跳过整个顶点；相等值保留先前位模式，包括正负零。12 字节顶点步长及不支持 SSE2 的构建使用原有标量规则。

这项改动不依赖 NVIDIA 接口；x64 的 Intel、AMD CPU 都可使用 SSE2 路径。本轮没有 AMD 实机性能数据。

诊断计时新增阴影范围计算及缓冲区锁定两个阶段。正式构建关闭 `MIKUDANCESTUDIO_PERF` 和 `MIKUDANCESTUDIO_DIAG`。

<a id="record-mme-preview-performance-abba-对照"></a>
### ABBA 对照

顺序为旧版、新版、新版、旧版。两种二进制使用相同测试宿主、设置和诊断计时；差异为原始标量范围扫描与 SSE2 范围扫描。基线建立在 `bd7ff2e` 的渲染实现上。

每轮按 100%、25%、25%、100% 顺序运行；每段预热 0.5 秒，测量至少 1.5 秒，在区间边界等待 GPU 完成。固定第 0 帧，关闭物理，使用 MMD 原始抗锯齿、固定阴影策略和未增强阴影滤波。吞吐按各段总帧数除以总耗时合并。

| 预览比例 | 旧版帧/秒 | 新版帧/秒 | 吞吐提升 | 旧版范围计算 | 新版范围计算 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100% | 43.68 | 47.72 | 9.25% | 3.743 ms/帧 | 1.922 ms/帧 |
| 25% | 43.37 | 49.01 | 13.01% | 3.784 ms/帧 | 1.878 ms/帧 |

这些短样本用于确认本次改动有收益，仍会受到调度和设备负载影响。最终关闭插桩后的尺寸检查仅作为功能验证，不与上表混用。各轮数据及二进制校验值见 [对照记录](data/mme-preview-performance.json)。

早期测试发现，测试宿主把模型 0 的指针赋给了当前选中槽位，导致多模型 PMM 重复持有同一模型，退出时重复释放。现已改为选择槽位 0，并检查所有已加载槽位的指针互不重复。上表四轮均使用修正后的宿主，均正常退出；早期异常样本未纳入统计。

### SMAA 菜单与验证

- SMAA 二级入口只展开子菜单，没有默认档位，也不再通过点击或 Enter 恢复上次所选。
- 选中 MSAA、FXAA 或 TAA 时，SMAA 二级及三级项目均不显示选择圆点。
- 选中 SMAA 时，二级入口和三级当前档位同时显示圆点。
- 中、英、日 README 已同步。
- 最终原生及真实 MME 抗锯齿回归分别通过 854 项，包含三种界面的菜单状态和时间抗锯齿检查。
- 预览缩放规则通过 411 项；顶点范围通过 144 组与标量实现的逐位比较，并通过既有投影覆盖检查。
- 最终 Stage 尺寸跟踪正常退出，PMM、EMM 未改变。
