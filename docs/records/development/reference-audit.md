<a id="record-verify-method-两次区域判错记录在此"></a>
### 两次区域判错，记录在此

**第一次：v1 与 v2 弄反。** 方法文件最初把 `0x140082E1C..0x140084472` 记作 **v2** 主体，
由此得出 `B3-01`「原版有界」的结论。实际 `0x140082D9C` 的 `je 0x140082e1c` 是
**`"0001"`** 的入口，那一区间是 **v1**；v2 走 `0x140078E30`。`B3-01` 的结论因此是在
v1 代码上得出的。

教训：分派处的条件跳转方向要按比较的串来读，不能按地址顺序猜。
`0x140082D9A` 的 `repe cmpsb [rsi],[rdi]` 里 `rdi` 指向 `"0001"`，`je` 成立即
「等于 0001」，所以跳转目标是 v1。

**第二次：把 v2 切窄了。** 改对之后把 v2 记成 `0x140078E30..0x14007D27D`，那只是
第一个 `.pdata` 片段。同一次判错的连锁后果是：首轮 v2 核验组在错误区间里得出了一批
看似完整的结论，全部作废重做。

教训：`.pdata` 的函数边界不等于控制流边界。这个 loader 由多个片段顺序贯穿而成，
判断范围要看片段之间的顺序落入与序言里 app 指针的重新取回，不能停在第一个
片段末尾。另外，核验组拿到任务给的区间后应自行复核锚点，而不是直接采信。

<a id="record-verify-method-判定标准"></a>
### 判定标准

对每一条，只回答一个问题：**原版在把该值用于越界访问之前，有没有做范围判断？**

三种结论：

| 结论 | 含义 | 处理 |
| --- | --- | --- |
| `原版无界` | 读到值后直接使用，中间无比较 | 按有意加固实现，注释注明原版无此判断 |
| `原版有界` | 有比较且越界会跳过或钳制 | **移植已忠实，不要改**；若移植缺这道界，则按移植缺陷修（照原版） |
| `无法定位` | 没找到对应代码 | 保留「未核验」，写清尝试过的定位路径 |

判定时必须区分两类比较，这是已踩过的坑：

- **合法性校验**：`cmp <读入值>, <上界>` 之后跟条件跳转，越界走另一条路。这类算界。
- **按容量遍历**：`loop: ... ; cmp <计数器>, <容量> ; jl loop`。这类是遍历整个池，
  不是校验某一个值，**不能当作参考界**。

`B3-01` 曾是这条判据被误用的例子。该条一度依据「`0x140083B54` 处为 `cmp dword ptr [rcx + 0x3110], esi` 加 `jle`，属于合法性校验」判为「原版有界、移植忠实」，但该地址实际位于 **v1** 载入器中（`0x3110` 对应 `ModelRecord::boneCount`，x64 为 12560）。v2 主体（`0x140078E30..0x140082BDB`）并无等价判断，因此 `B3-01` 的最终结论是原版无界、按加固处理。键池容量（`0x927c0`，即 600000）在载入器区间内未出现，在其他位置的出现形式是 `0x14003A740` 处的遍历循环。

<a id="record-verify-method-输出格式"></a>
### 输出格式

每条一行，另附证据：

```
### <编号> <位置>
- 结论: 原版无界 / 原版有界 / 无法定位
- 原版证据: 0x<地址> 起若干条指令（贴原始字节与反汇编）
- 字段对照: 原版位移 -> 头文件字段名（例如 0x3110 -> ModelRecord::boneCount）+ 字节数
- 处理: 加固（附要覆盖的全部取用点） / 不要改（说明移植哪一行已忠实） / 待核验
- 置信度: 高 / 中 / 低
```

<a id="record-verify-method-纪律"></a>
### 纪律

- 每个结论都要有地址和指令作依据。没有地址的结论写「无法定位」。
- 位移必须换算成头文件里的字段名再下结论。端口注释里的 x86 偏移与 x64 不同，
  例如 `boneCount` x86 是 11652、x64 是 12560。
- 不要因为条目分类相同就推定结论相同。`B3-01` 与 `B3-05` 同属「文件数据当索引」，
  但一条原版有界、一条没有。
- 本轮不改代码，只出核验结论。

<a id="record-verify-method-运行时地址引用的换算"></a>
### 运行时地址引用的换算

源码注释里有 564 处形如 `0x7FF7CB4FB4B0` 的地址，是某一进程内的运行时地址。
换算公式是：

```text
文件 VA = 0x140000000 + (运行时地址 - 0x7FF7CB420000)
```

三个已验锚点：

| 运行时地址 | 文件 VA | 结论 |
| --- | --- | --- |
| `0x7FF7CB4DB0CD` | `0x1400BB0CD` | 在 `.text` 内 |
| `0x7FF7CB4EFED0` | `0x1400CFED0` | 在 `.text` 内 |
| `0x7FF7CB4E9958` | `0x1400C9958` | 在 `.text` 内 |

所以这批引用是**可用**的，可以直接按公式换算后核验。

一次判错记录：本文档早先写过「这些引用无法换算」，依据是按 64 KB 步长在
`0x7FF7CB000000..0x7FF7CB600000` 内穷举基址失败。真实基址 `0x7FF7CB420000`
不在 64 KB 网格上，所以那次搜索必然漏掉。教训是穷举基址要覆盖非对齐取值，
或者直接从已知代码里取一个锚点反解，不要靠网格搜索。
