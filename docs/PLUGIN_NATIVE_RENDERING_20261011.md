# 插件默认绘制与原生阴影修复

## 修复内容

完整包关闭透明排序时保持既有原生“不透明、透明”两遍顺序。此前仅加载 MME 就会改成单遍，导致相同场景的遮挡改变；本次移除了该特殊分支。MMV 主场景使用宿主给出的材质分类，保留组内对象和材质顺序及附件边界。自定义 FX 仍只提交一次，不增加默认材质的实心纹素预遍历。

MMV 的新帧尾部接收本帧原生 R32F 自阴影贴图、投影矩阵、尺寸与模式。两端共用 DX9 设备，传递 GPU 引用，不逐帧回读 CPU。宿主检查阴影绘制与状态恢复结果，失败时清除输出，避免显示旧帧。MMV 有变形、删面或隐藏输出时，按同一原生矩阵重画完整阴影，避免保留变形前的投影。

MMV 内建默认着色器的技术名原先与输出目标 `Main` 重名，技术选择优先命中了无阴影路径；现改为专用技术名。外部 FX 的名称和选择优先级未改。

`MmvMmsFrame` 仅追加按长度检查的可选尾部；不改变嵌入场景和材质数组步长。旧调用方保留旧行为。此修复需要配套的新 MMS 和 MMV4MMS；MME 和 MMV 仍分别启用。

动态缩放开启时，三语面板改为左“高”、右“低”。关闭动态缩放时沿用原范围标签。

## 验收

| 范围 | 结果 |
| --- | --- |
| 原生与真实 MME | 阴影 0/2、Off→Low→Off 共 6 组：绘制序列一致，RGB 差异 0；每帧包含有效半透明遮挡像素 |
| GoldBoom 与 GoldBoomDiffuse | 两次手选同名 FX；7 个捕获阶段 RGB 差异 0，模型未消失 |
| MMV 材质顺序 | 实际 GPU 覆盖、单次混合、自定义 FX、旧接口长度、失败恢复通过 |
| MMV 原生阴影 | 模式 1/2、同帧/同设备、错误输入、设备重置与真实网格变形测试通过；测试记录 CPU 读取次数为 0 |
| MMS→MMV 真实接入 | 207 项检查通过；真实 FrameDriver、贴图身份、矩阵、模式与距离变化，受控 Clear 失败及下一帧恢复；窗口隐藏且不激活 |
| 完整包 | 关闭排序、材质分类、PMD 索引、原生阴影及设备恢复通过 |

没有进行帧率基准，不据此宣称性能提高。有变形输出时会重画阴影，实际成本取决于场景。

## 已知限制

发布时扩大的透明排序回归有 5 项失败：`occlusion` 为 212 个像素断言，`low_alpha` 与 `maximum_limit`（各含 MSAA）各 9 个；提交 `12f75de` 的不可变发布源码结果逐条相同。后续逐项隔离发现测试遗漏纹理查询缓存失效、使用关闭排序的默认值，以及保留了已撤回的阴影遮罩实验断言。测试条件与当前功能的区别、复测结果见[透明排序回归复核](TRANSPARENT_SORT_VALIDATION_20261011.md)。这次复核不改变本发布的透明排序算法或阴影行为。

最小档不编入透明排序或 MMV。其格式边界与双向互导待验收状态见 [原版兼容构建档](ORIGINAL_PROFILE.md)。
