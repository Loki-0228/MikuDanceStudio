# 文档组织规则

先判断读者要完成什么，再选择文档位置。

| 位置 | 放什么 |
| --- | --- |
| `guides/` | 当前操作、常见问题和功能入口 |
| `reference/` | 格式、字段、兼容边界和构建档范围 |
| `development/` | 构建、测试、测量、接口和维护方法 |
| `records/` | 按功能归并的实现依据、诊断与验收记录 |
| `records/*/data/` | 与专题相邻的原始测量数据 |
| `images/`、`ui/` | 文档图片和界面参考资源 |

## 更新现有主题

功能行为变化时更新对应指南或参考页。一次修复的原因、前后版本和验证结果补入对应专题记录，不为每次操作新增日期命名文件。

同一事实只在主要文档完整说明，其他页面通过链接引用。发布说明集中在[发布记录](../records/releases.md)，使用指南不承担逐次发布日志。

## 保留记录的适用范围

记录必须注明源码或二进制身份、配置、素材和验证范围。日期可作为元数据，不能单独证明内容仍适用于当前版本。

历史正文中的「当前」「已通过」只代表该次记录。合并资料时保留原有失败与限制，不把未完成方案改写成已实现功能。本地证据缺失时明确标注，不伪造可下载链接。

## 修改路径后检查引用

移动或合并页面时同步修改仓库首页、文档内链、测试说明和源码注释。合并后的每份原记录使用固定锚点，指向旧页面的链接应到达对应记录。

检查相对路径、页内锚点、图片与数据文件，并执行 `git diff --check`。文档调整不需要重建渲染程序；只有修改实际构建输入或测试逻辑时才运行相应检查。
