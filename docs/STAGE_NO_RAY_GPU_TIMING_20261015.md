# StageNoRay 缩小预览后的 GPU 绘制耗时

后续已加入未变化模型的顶点缓存，StageNoRay 与 ray 的前后对照见 [模型顶点缓存验证](MODEL_VERTEX_CACHE_20261015.md)。下文保留缓存加入前的计时结果。

缩小预览确实减少了 GPU 绘制区间的耗时。后两轮相邻复测中，100% 预览平均为 13.32 ms，25% 为 10.75 ms，减少 2.57 ms，约 19.3%。同两轮的整帧平均耗时为 16.25 ms 和 16.10 ms，差约 1%，小于运行波动，不能认定整帧已经提速。

本轮增加了隐藏测试宿主的计时能力，没有修改正式程序的绘制实现。前序模型优化和尺寸核对见 [StageNoRay 性能报告](STAGE_NO_RAY_PERFORMANCE_20261015.md)。三轮汇总、每段结果及原始记录校验值见 [GPU 计时数据](STAGE_NO_RAY_GPU_TIMING_20261015.json)。

## 测量范围

工程为 `D:/MMD-Next/tests/ToonGlass_Ray/UserFile/StageNoRay.pmm`，显卡为 NVIDIA GeForce RTX 4070 Laptop GPU。隐藏宿主加载真实 MME，保留工程的抗锯齿和阴影设置，关闭物理与地面网格，固定第 0 帧重复绘制。运行期间没有构建，也没有截图读回。该测试衡量固定场景的渲染耗时，不代表动画播放帧率。

主画面实际尺寸从 725×406 降到 181×102，宿主阴影从 8192×8192 降到 2048×2048。25% 表示宽、高各缩小到约四分之一，主画面像素数量减少约 94%。本轮比较包含现有的阴影尺寸调整，不能将收益全部归因于主画面。

每轮依次测量 100%、25%、25%、100%。每段包含三个独立采样区间：

- 128 帧 CPU 计时，只记录模型更新、绘制提交、预览放大和 Present 的经过时间。
- 32 帧 GPU 计时，在场景、抗锯齿完成、预览放大和 HUD 边界放置五个时间戳。整批提交后才读取查询结果，不逐帧等待 GPU。
- 至少 4 秒的整帧测量，移除观察钩子，不插入 GPU 时间戳，最后等待已提交的 GPU 工作完成。总耗时除以帧数得到 ms/帧。

GPU 区间从第一次场景 Clear 开始，到 HUD 完成结束。模型准备发生在区间之前，Present 发生在区间之后。区间可能包含 GPU 等待 CPU 提交命令的空隙，因此不能称为纯 GPU 忙碌时间。本机不支持可选的管线空闲占比查询，记录值为 `D3DERR_NOTAVAILABLE`。时间戳及频率、有效性查询的含义参见 Microsoft 的 [D3D9 查询说明](https://learn.microsoft.com/en-us/windows/win32/direct3d9/queries)。

## GPU 分段结果

下表合并 `async-2` 和 `async-3`，每个比例各 128 个有效 GPU 帧。GPU 总区间为四个相邻分段之和。CPU 与 GPU 在正常运行时可以重叠，不能将后文的 CPU 时间加到本表中。

| GPU 区间 | 100% 预览 | 25% 预览 |
| --- | ---: | ---: |
| 场景及 MME 绘制 | 13.280 ms | 10.681 ms |
| 场景结束后的抗锯齿处理 | <0.001 ms | <0.001 ms |
| 预览放大及边缘处理 | <0.001 ms | 0.027 ms |
| HUD 绘制 | 0.041 ms | 0.043 ms |
| 总区间 | 13.321 ms | 10.750 ms |

当前工程使用的路径没有单独的 TAA 或 SMAA 后处理负担，抗锯齿分段接近计时分辨率。这组数据不能用于比较各抗锯齿算法的性能。

放大回窗口尺寸只占约 0.03 ms 的 GPU 区间，不能解释整帧约 16 ms 的耗时。MME 的场景绘制仍占主要 GPU 区间。

## 整帧耗时与重复性

三轮的时间戳均有效，全部保留在数据文件中。第一轮的 CPU 经过时间明显更长，100% 下两个整帧采样段从 35.17 ms 降到 27.97 ms，极差约占中位数的 22.8%。运行条件存在漂移，未将第一轮混入后两轮平均值。

| 轮次 | GPU 100% | GPU 25% | GPU 区间缩短 | 整帧 100% | 整帧 25% | 整帧耗时变化 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| async-1，运行状态漂移 | 14.142 ms | 12.989 ms | 8.15% | 31.153 ms | 27.893 ms | 减少 10.46%，不作稳定收益 |
| async-2 | 13.199 ms | 10.612 ms | 19.60% | 15.953 ms | 16.038 ms | 增加 0.53% |
| async-3 | 13.442 ms | 10.888 ms | 19.00% | 16.568 ms | 16.153 ms | 减少 2.50% |
| 后两轮合并 | 13.321 ms | 10.750 ms | 19.30% | 16.255 ms | 16.095 ms | 减少 0.98%，未确认提速 |

整帧合并按总耗时除以总帧数计算。后两轮共有 1,986 个整帧样本。100% 的四段均值范围为 15.94～17.00 ms，25% 为 15.90～16.20 ms。第三轮 100% 两段的极差约占中位数的 5.1%，所以约 1% 的合并差异不构成明显提速的证据。

三轮均连接电源，使用相同测试程序。后两轮的活跃 GPU 遥测记录和各轮频率、功耗范围保存在 JSON 中。遥测包括加载和预热，不能精确归属到某个采样段。第一轮与后两轮 CPU 时间差异的外部原因尚未确定。

## 限制收益的工作

下表来自独立的 CPU 计时区间，合并后两轮，每个比例各 512 帧。经过时间包含驱动处理与等待，不等于纯 CPU 指令执行时间。

| CPU 经过时间 | 100% 预览 | 25% 预览 |
| --- | ---: | ---: |
| 模型更新，包含在场景准备中 | 9.788 ms | 9.239 ms |
| 场景及 MME 提交 | 6.717 ms | 6.415 ms |
| 预览放大调用 | <0.001 ms | 0.136 ms |
| HUD 提交 | 0.040 ms | 0.022 ms |
| Present 调用 | 0.788 ms | 0.482 ms |

缩小像素尺寸后，每帧仍更新全部 6 个模型。前序目标追踪还确认，几何提交量基本不变，MME 中仍有固定尺寸的软阴影、亮度统计、材质和粒子数据目标。因此，GPU 绘制区间缩短约 2.6 ms 后，模型处理和绘制提交仍足以限制整帧速度。

这些结果支持继续定位模型更新和 MME 提交中的固定工作，而不能仅凭缩小纹理预测帧率提升。具体等待位置尚未分离，不将 CPU 调用耗时全归为计算成本。CPU 调用和 GPU 执行的区别参见 Microsoft 的 [Direct3D 调用性能分析说明](https://learn.microsoft.com/en-us/windows/win32/direct3d9/accurately-profiling-direct3d-api-calls)。
