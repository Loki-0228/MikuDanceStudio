# 透明材质绘制合批验收

本轮由主任务直接修改原生透明绘制。Rou 的透明排序把三个水晶材质交错排列，导致约 1.4 万次材质绘制调用。新增合批保留可能覆盖同一像素的三角面顺序，只移动互不影响的部分。

## 实现与限制

`transparent_geometry::BatchDraws` 在现有 `Order` 完成后运行，不更改排序档位的算法。屏幕分为 256 × 256 个区域；三角面包围盒各向外扩展一个像素。同一区域的三角面按输入顺序建立依赖，按材质选择已经满足依赖的三角面。重复来源编号的切割碎片仍按序列位置区分。

分析预算为 2,000,000 次区域访问。预算不足、投影无效或绘制段数没有减少时保留原序列。缓存包含视口尺寸和 MME 加载状态。顶点、UV、法线、材质与三角面数量不变。

目前仅在未加载 `MMEffect.dll` 时启用。未知 FX 可能移动顶点或在源三角面之外产生输出，因此不能直接按原网格推断遮挡。原生 alpha 为零的隐藏材质也不再进入透明排序；MME 存在时保留原分类，因为 FX 可能修改最终 alpha。不能将本轮收益表述为所有 MME 效果的性能收益。

## 正确性验证

- `transparent_geometry_tests` 通过。覆盖重叠顺序、共边、亚像素间隙、同材质不同颜色、重复来源编号、稀疏材质编号、预算回退和顶点数据完整性。
- `model_alpha_tests` 通过。
- `model_alpha_occlusion_tests --intersections` 及 `--intersections --msaa` 通过。新增 GPU 合批用例必须实际减少绘制段，然后比较全部 9,216 个像素；单采样与 4 倍抗锯齿结果均与原序列逐像素相同。
- Rou 的完整运行画面前后差异为 92 个像素；修改前同版本重复运行也有 199 个像素差异。因此没有声称完整模型画面逐像素相同。静态诊断绕过完整 `FrameDriver` 后材质初始化不完整，其画面不能作为验收依据。

逐对检查全部三角面的首个原型增加了 CPU 开销，已放弃；`after-smoke.*` 保留失败样本，不纳入收益。`rou-order.*`、`rou-orbit.*` 使用正斜杠场景路径，未完整解析材质贴图，亦不纳入性能验收；有效采样使用原生 Windows 路径。

## FX 最终透明度的后续优化

当前分类依据材质与贴图原始 alpha。若 FX 的最终输出只含全透明和全不透明像素，可以考虑透明度裁切和不透明绘制；仍存在半透明像素时仍需要相应合成。跳过整块材质需要能够证明它没有任何输出。单帧看不见、局部被裁切或原始贴图透明，都不足以支持永久跳过。

该分类必须随 FX、参数、纹理和时间变化失效重算。现阶段未改变外部 FX 的分类契约。
