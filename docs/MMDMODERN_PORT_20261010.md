# MMDModern 查找优化移植与前后对比

后续新增的汉化适配包及崩溃风险核对见[新版 DLL 静态审计](MMDMODERN_NEW_DLL_AUDIT_20261010.md)。该核对发现新包默认关闭 `DrawOrderTable`，尚未确认用户提到的旧版崩溃原因。

## 移植范围

本次把 MMDModern 的三项查找优化写入 MMS 源码。没有把 `dsound.dll` 放入发布目录。

| DLL 机制 | 本次实现 | 保留的行为 |
| --- | --- | --- |
| `DrawOrderTable` | 每次遍历建立顺序表，覆盖模型主通道、透明排序收集、描边、投影阴影和配件固定/效果通道 | 重复顺序取第一个槽，每次遍历重新解析宿主或插件对象；原来按槽渲染的阴影图通道保持按槽顺序 |
| `TextureLookupHash` | 纹理名称、颜色和 Alpha 查询共用哈希索引，纹理新增、重载、重建及销毁时失效 | UTF-16 路径精确且区分大小写，第一个同名项优先，遇空项结束，读取实时 COM 对象和标签 |
| `CurrentObjectCache` | 缓存 MME 当前对象的查询结果 | 仅渲染线程命中，按对象、注册代次、重复通道、分割顺序和对象顺序校验，场景变更时失效 |

当前基线已包含前一轮的两个模型主通道顺序表。本报告测量本轮新增优化的收益，没有把较早优化重复计入。

二进制依据：`D:/MMD-Next/refs/MMDModern/dsound.dll`，SHA-256 为 `B91D627D0D245D49A93D845278464C708EE7DD3E34686FA4CFCF58A6A4E1F9E1`。此前静态分析定位的入口包括顺序表 `DLL+0x6730/0x67c0`、纹理索引 `DLL+0x73c0/0x8080` 和当前对象缓存 `DLL+0xdc10`。源码实现用宿主生命周期替代 DLL 的补丁地址及内存探测。

`SkipUndrawnObjects`、`DeferBuiltinEffect`、MME 文件检查限频、AVI 异步回读、FastFork 和高精度等待未在本次移植。前两项依赖 MME 内部状态及副作用契约，不能仅凭“无可见输出”跳过宿主绘制。文件加载、效果编译、纹理解码和导出速度也不属于本次帧率结果的验证范围。原项目已有顺序文件读取缓冲，本次没有重复添加。

## 播放测量方法

场景为 `D:/MMD-Next/tests/ToonGlass_Ray/UserFile/Stage.pmm`，完整加载 11 个模型、8 个配件、741746 个顶点、187 个刚体和 273 个约束。显卡为 NVIDIA GeForce RTX 4070 Laptop GPU。两侧固定 CPU 蒙皮，视口为 960×540，实际公共渲染目标为 1463×914，美影 4096、场景自阴影模式 1；透明排序保留该场景默认关闭状态。物理、描边和 MME 效果继续执行。

每次运行用独立的资源和设置副本。程序隐藏但不最小化，运行正常播放推进、物理更新、效果和 Present，记录每帧完成时间、成功 Present 数、宿主绘制提交数、三角形等图元提交数和实际播放游标。MME 场景每个采样帧均提交 1118 次绘制、6963591 个图元，并有一次成功 Present。

所有播放组均按前、后、后、前交替两轮。早期组每次预热后采样 15 秒，后续 2% 长采样为 45 秒。启动消息处理可能占用名义预热时间，因此每次统一排除 CSV 前 5000 毫秒，按余下首末帧边界计算约 10 秒或 40 秒的帧率。原始全段结果不覆盖，各组分别汇总。最后列出四次样本的中位数、范围及每轮变化；同版本极差超过中位数 5% 时标记波动。

此 FPS 是后台播放中成功调用 Present 的频率，不能代表桌面合成后的显示刷新率。系统原生 D3D9 会切换内部调用表，当前观察器在该路径计数失效。失败记录保留且排除，原生路径只用 GPU 排空后的批次帧耗时对照。

基线封存时存在尚未被任何基线源码引用的未跟踪 `texture_lookup.hpp`，状态已如实保存；该头文件没有参与基线编译。

## 资源限制与遥测

机器为 Intel Core i9-13900HX，24 个物理核心、32 个逻辑处理器。测试固定在逻辑处理器 4、6，分别属于两个性能核心，亲和性掩码为 `0x50`。使用 Windows Job Object 的硬 CPU 上限，2% 对应 `CpuRate=200`、`ControlFlags=5`。
